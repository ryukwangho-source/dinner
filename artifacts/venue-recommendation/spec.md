## 개요

직장인이 회식 장소를 정할 때 지역·인원수·인원당 예산만 입력하면, 평점·리뷰수·조회수가 좋은 장소 중 예산에 맞는 순으로 상위 5곳을 추천받는다. 마음에 드는 장소를 여러 개 골라 저장하거나, 추천 결과 전체를 카톡으로 공유할 수 있다.

## 범위

### 포함
- 지역(드롭다운)·인원수·인원당 가용예산 입력 → 상위 5곳 추천
- 예산에 가까운 장소가 우선 노출되고, 예산을 초과하는 장소도 참고용으로 함께 노출
- 추천 결과에서 장소를 여러 개 선택해 한 번에 저장 (로그인 불필요, 잠금 없음)
- 추천 결과 5곳 전체를 카톡 등으로 한 번에 공유 (모바일 OS 공유 시트, 데스크톱은 클립보드 복사)
- 저장된 장소 전체를 모아보는 별도 목록 화면, 개별 삭제와 전체 삭제

### 제외
- 실시간 외부 리뷰·조회수 API 연동 — 이번 범위는 직접 큐레이션한 시드 데이터로 추천 로직만 검증한다. 실 데이터 연동은 별도 feature로 다룬다.
- 지역 자유 텍스트 입력 — 시드 데이터에 없는 지역을 입력해 빈 결과가 나오는 상황을 막기 위해, 이번 범위는 미리 정의된 지역 목록에서만 선택한다.
- 저장·삭제에 대한 비밀번호 보호 — 사용자가 잠금 없이 누구나 저장·삭제 가능하길 원했다.
- 장소 예약·주문 연동 — 추천과 공유까지만 다룬다.
- 로그인/계정, 기기 간 개인화 — 저장 목록은 개인별이 아니라 전체 사용자가 공유하는 목록이다 (travel의 여행 목록과 동일한 모델).
- "최근 기준" 실시간 필터링 — 시드 데이터는 수동 큐레이션이라 실시간으로 최신순을 갱신하지 않는다. 데이터 자체를 최신 상태로 유지하는 것은 운영 작업이며 이번 feature 범위 밖이다.

## 시나리오

### 1. 기본 추천 받기
- **Given** 사용자가 홈 화면의 입력 폼을 보고 있다
- **When** 지역 드롭다운에서 "강남역"을 선택하고, 인원수에 "8", 인원당 가용예산에 "30000"을 입력한 뒤 "추천받기" 버튼을 클릭한다
- **Then** 결과 화면으로 이동하며, "강남역" 시드 데이터 중 예산 적합도·평점·리뷰수·조회수를 반영한 상위 5곳이 카드 목록으로 표시된다

성공 기준:
- [ ] 지역="강남역", 인원수=8, 예산=30000 입력 → 결과 화면에 장소 카드가 정확히 5개(시드 데이터가 5곳 이상일 때) 표시된다
- [ ] 각 카드에는 장소명, 카테고리, 평점, 리뷰수, 조회수, 1인 예상 비용이 표시된다

### 2. 예산 우선순위 반영
- **Given** 선택한 지역의 시드 데이터에 예산 이내 장소와 예산을 초과하는 장소가 섞여 있다
- **When** 추천 결과가 표시된다
- **Then** 예산 이내 장소들이 예산을 초과하는 장소보다 항상 위쪽에 노출되고, 초과 장소에는 "예산 초과" 표시가 붙는다

성공 기준:
- [ ] 예산 이내 장소 A(1인 25,000원)와 예산 초과 장소 B(1인 40,000원)가 후보일 때, 예산 30,000원 기준으로 A가 B보다 항상 먼저 나열된다
- [ ] 예산을 초과하는 카드에는 "예산 초과" 배지가 보인다

### 3. 예산 이내 장소가 하나도 없을 때
- **Given** 선택한 지역의 모든 시드 데이터가 입력한 예산을 초과한다
- **When** 추천 결과가 표시된다
- **Then** 예산 이내 장소가 없다는 안내 문구와 함께, 예산에 가장 가까운 순으로 상위 5곳이 "예산 초과" 표시와 함께 그대로 노출된다

성공 기준:
- [ ] 후보 전원이 예산 초과인 지역 선택 → "예산에 맞는 장소가 없어 가까운 순으로 보여드려요" 문구가 나타나고 카드 5개는 그대로 표시된다

### 4. 시드 데이터가 5곳 미만인 지역
- **Given** 선택한 지역에 등록된 시드 장소가 3곳뿐이다
- **When** 추천 결과가 표시된다
- **Then** 있는 3곳만 카드로 표시되고, 5개를 채우기 위한 다른 지역 장소는 섞이지 않는다

성공 기준:
- [ ] 시드 장소 3곳뿐인 지역 선택 → 카드가 정확히 3개 표시된다

### 5. 여러 장소 선택 후 저장
- **Given** 추천 결과 화면에 카드 5개가 표시되어 있다
- **When** 카드 2개의 체크박스를 선택하고 "선택한 장소 저장" 버튼을 클릭한다
- **Then** 선택한 2개 장소가 저장되었다는 안내가 나타나고, 저장 목록 화면에서 그 2곳을 확인할 수 있다

성공 기준:
- [ ] 카드 2개 체크 → 저장 버튼 클릭 → "2곳을 저장했어요" 같은 확인 메시지가 나타난다
- [ ] 저장 목록 화면 진입 → 방금 저장한 2개 장소가 목록에 보인다

### 6. 아무것도 선택하지 않고 저장 시도
- **Given** 추천 결과 화면에서 체크된 카드가 없다
- **When** "선택한 장소 저장" 버튼을 클릭(또는 버튼이 비활성 상태)한다
- **Then** 저장이 실행되지 않고, 최소 1곳을 선택해야 한다는 안내가 표시된다

성공 기준:
- [ ] 선택 없이 저장 시도 → "저장할 장소를 선택해주세요" 안내가 나타나고 저장 목록은 변하지 않는다

### 7. 추천 결과 카톡 공유
- **Given** 추천 결과 화면에 카드 5개가 표시되어 있다
- **When** "카톡으로 공유하기" 버튼을 클릭한다
- **Then** 모바일에서는 OS 공유 시트가 열려 카카오톡을 포함한 공유 대상 앱을 고를 수 있고, 공유 시트를 지원하지 않는 환경(주로 데스크톱)에서는 5곳 목록이 텍스트로 클립보드에 복사되었다는 안내가 표시된다

성공 기준:
- [ ] Web Share API 지원 환경에서 공유 버튼 클릭 → OS 공유 시트가 호출된다
- [ ] Web Share API 미지원 환경에서 공유 버튼 클릭 → "클립보드에 복사했어요" 안내가 나타나고 클립보드에 5곳 이름이 포함된 텍스트가 담긴다

### 8. 저장 목록 조회
- **Given** 저장된 장소가 여러 건 존재한다
- **When** 사용자가 저장 목록 화면에 진입한다
- **Then** 저장된 모든 장소가 최근 저장 순으로 표시된다 (누가 저장했는지 구분 없이 전체 공유 목록)

성공 기준:
- [ ] 저장 목록 화면 진입 → 저장된 장소가 저장 시각 역순(최근 저장이 위)으로 표시된다

### 9. 저장 목록에서 개별 삭제
- **Given** 저장 목록에 장소 A, B가 있다
- **When** 장소 A의 "삭제" 버튼을 클릭한다
- **Then** 장소 A는 목록에서 사라지고 장소 B는 그대로 남는다

성공 기준:
- [ ] 장소 A 삭제 클릭 → 목록에서 A가 사라지고 개수가 1 감소한다

### 10. 저장 목록 전체 삭제
- **Given** 저장 목록에 장소가 여러 건 있다
- **When** "모두 삭제" 버튼을 클릭하고 확인한다
- **Then** 저장 목록이 비워지고, 빈 상태 안내 문구가 표시된다

성공 기준:
- [ ] 장소 3건이 있는 상태에서 "모두 삭제" 확인 → 목록이 0건이 되고 "저장된 장소가 없어요" 같은 빈 상태 문구가 나타난다

### 11. 입력값 미완성
- **Given** 사용자가 홈 화면 입력 폼에서 지역만 선택하고 인원수·예산은 비워 두었다
- **When** "추천받기" 버튼을 클릭한다
- **Then** 결과 화면으로 이동하지 않고, 비어 있는 필드 아래 입력을 요청하는 안내가 표시된다

성공 기준:
- [ ] 인원수·예산 미입력 상태로 추천받기 클릭 → 각 필드 아래 "입력해주세요" 안내가 나타나고 화면 전환은 일어나지 않는다

## 불변 규칙

- 저장·삭제는 누구나(로그인·비밀번호 없이) 수행할 수 있다. 어떤 화면에서도 저장·삭제 전에 인증을 요구하지 않는다.
- 예산 이내 장소는 정렬 순서상 예산 초과 장소보다 항상 앞에 나온다 (시나리오 2, 3에 걸쳐 유지).
- 저장 목록은 개인별로 분리되지 않는다 — 누가 저장했든 같은 저장 목록에 모인다.

## 의존성

- 지역·장소 시드 데이터(장소명, 카테고리, 지역, 평점, 리뷰수, 조회수, 1인 예상 비용)가 이 feature 시작 전에 준비되어 있어야 한다. 데이터를 채우는 방법(수동 입력 스크립트, 관리자 화면 등)은 plan.md에서 정한다.
