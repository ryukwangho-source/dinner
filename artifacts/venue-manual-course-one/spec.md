## 개요

현재 홈 화면은 지역명을 입력하면 1차·2차를 함께 자동 추천한다. 이 feature는 사용자가 1차(식사) 장소를 직접 지정할 수 있는 모드를 추가한다 — 지정한 장소의 평점·리뷰수·조회수를 조사해 보여주고, 그 장소 기준 도보 10분 이내 2차(가볍게 한잔) 장소 5곳을 추천한다.

## 범위

### 포함
- 홈 화면에서 "지역으로 추천받기" / "1차 장소 직접 입력" 두 모드를 토글로 전환할 수 있다
- 1차 직접 입력 모드에서는 1차 장소명 하나·인원수·인원당 예산을 입력한다 (지역 입력 없음)
- "추천받기" 클릭 시 결과 화면으로 이동해, 입력한 1차 장소를 웹검색으로 조사해 평점·리뷰수·조회수를 카드로 보여준다
- 조사된 1차 장소를 기준으로 도보 10분 이내 2차 업종(이자카야·호프) 장소를 조사해 예산 적합도 우선으로 상위 5곳을 카드로 보여준다
- 이 흐름에서 나온 1차·2차 장소도 기존 저장·카톡 공유·투표 만들기 기능이 동일하게 동작한다
- 생성은 기존 지역 흐름과 동일하게 백그라운드로 진행되고, 화면 이탈·새로고침에도 지속된다
- 같은 1차 장소명·인원수·예산 조합은 6시간 캐시로 재사용한다 (기존 지역 흐름과 동일한 캐시 정책)
- 생성 실패(장소를 찾지 못함 등) 시 기존 지역 흐름과 동일한 실패 안내 + 재시도 버튼을 보여준다
- 입력한 1차 장소명은 회식 업종(고깃집·일식 등) 화이트리스트 검증 없이 그대로 받는다 — 사용자가 이미 선택한 장소이므로

### 제외
- 한 번에 여러 1차 장소 입력 — 이번 feature는 1차 장소 하나 기준으로만 동작한다. 여러 개 동시 조사는 범위 밖(필요해지면 별도 요청으로 다룬다)
- 1차 장소명 자체에 대한 업종 검증·거부 — 카페 등 회식과 무관해 보이는 이름이어도 시스템이 대신 판단하지 않는다
- 기존 지역 기반 자동 추천(1차) 로직 변경 — 그대로 둔다

## 시나리오

### 1. 1차 장소를 직접 입력해 2차 추천받기 (happy path)
- **Given** 사용자가 홈 화면에서 "1차 장소 직접 입력" 모드로 전환했다
- **When** 1차 장소명("브리비트 강남역점"), 인원수(8), 인원당 예산(30000)을 입력하고 "추천받기"를 클릭한다
- **Then** 결과 화면으로 이동해 진행 중 안내가 먼저 보이고, 완료되면 입력한 1차 장소 카드(평점·리뷰수·조회수 포함)와 그 장소 기준 도보 10분 이내 2차 카드 5개가 표시된다

성공 기준:
- [ ] 1차 장소명="브리비트 강남역점" 입력 → 결과 화면에 "브리비트 강남역점" 이름의 카드 1개가 평점·리뷰수·조회수와 함께 표시된다
- [ ] 2차 카드 5개가 표시되고, 각 카드에 도보 시간이 10분 이내로 표시된다
- [ ] 2차 카드들의 평점·리뷰수·조회수는 하드코딩값이 아니라 이번 조사 결과다

### 2. 결과 화면의 그룹 제목 표시
- **Given** 1차 장소 직접 입력으로 생성이 완료됐다
- **When** 결과 화면을 본다
- **Then** 지역 흐름에서 지역명이 나오던 자리에 입력한 1차 장소명이 그대로 그룹 제목으로 표시된다

성공 기준:
- [ ] 결과 화면 그룹 제목에 입력한 1차 장소명("브리비트 강남역점")이 그대로 표시된다

### 3. 같은 조합 재요청 시 캐시 재사용
- **Given** 같은 1차 장소명·인원수·예산 조합으로 5분 전에 이미 추천을 받은 적이 있다
- **When** 같은 조합으로 다시 "추천받기"를 클릭한다
- **Then** 새로 검색하지 않고 대기 화면 없이 즉시 이전 결과가 그대로 표시된다

성공 기준:
- [ ] 6시간 이내 동일 조합 재요청 → 진행 중 안내 없이 즉시 1차·2차 카드가 표시된다
- [ ] 6시간이 지난 뒤 동일 조합 재요청 → 다시 웹검색이 진행되고 새 결과가 나올 수 있다

### 4. 1차 장소를 찾지 못해 생성 실패
- **Given** 입력한 1차 장소명을 웹검색으로 확인할 수 없다 (오타·존재하지 않는 이름 등)
- **When** 생성이 실패로 끝난다
- **Then** 실패 안내와 "다시 시도" 버튼이 표시되고, 빈 카드나 대체 데이터로 넘어가지 않는다

성공 기준:
- [ ] 생성 실패 → 실패 안내 문구와 "다시 시도" 버튼이 보이고, 카드가 비어 있거나 대체되지 않는다
- [ ] "다시 시도" 클릭 → 같은 입력으로 새 생성이 시작되고 진행 중 안내로 돌아간다

### 5. 회식과 무관해 보이는 업종도 그대로 받는다
- **Given** 사용자가 입력한 1차 장소명이 카페처럼 회식과 무관해 보이는 업종이다
- **When** 생성이 완료된다
- **Then** 시스템은 업종을 이유로 거부하지 않고 그 장소를 1차 카드로 그대로 보여준다

성공 기준:
- [ ] 회식 업종 화이트리스트에 없는 이름의 장소를 입력해도 실패 처리되지 않고 1차 카드가 표시된다

### 6. 생성된 장소 저장·공유·투표
- **Given** 1차 직접 입력으로 나온 1차 카드 1개·2차 카드 5개가 화면에 표시되어 있다
- **When** 카드 몇 개를 선택해 저장하거나, 카톡으로 공유하거나, 투표를 만든다
- **Then** 지역 기반 흐름과 동일하게 저장 목록에 반영되고, 공유 텍스트에 포함되고, 투표 후보로 등록된다

성공 기준:
- [ ] 카드 2개 선택 후 저장 → 저장 목록에서 그 2곳이 정상적으로 보인다
- [ ] 카드들로 카톡 공유 → 공유 텍스트에 이름이 모두 포함된다
- [ ] 카드 일부를 후보로 투표 만들기 → 투표 화면에서 정상적으로 등록되고 득표할 수 있다

## 불변 규칙

- 생성 실패는 빈 결과나 대체 데이터로 조용히 넘어가지 않고 항상 사용자에게 실패로 보여진다 (기존 지역 흐름과 동일)
- 화면에 표시되는 평점·리뷰수·조회수는 항상 이번 조사 시점의 값이며 고정 상수로 대체되지 않는다
- 저장·카톡 공유·투표 기능은 장소 출처(지역 자동 추천 vs 1차 직접 입력)와 무관하게 동일하게 동작한다

## 의존성

- 기존 venue-live-generation 기능(백그라운드 생성 job, 결과 화면, 저장·투표·카톡 공유)이 이미 구현되어 있어야 한다
