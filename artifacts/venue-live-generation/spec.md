## 개요

기존 venue-recommendation은 수동으로 큐레이션한 시드 데이터(config/venues.ts)로 회식 장소를 추천했다. 이 feature는 그 데이터 소스를 실시간 웹검색 기반 생성으로 바꾼다 — 평점·리뷰수가 매 검색마다 새로 조사된 실측치가 되고, 더 이상 고정된 큐레이션 값이 아니다.

## 범위

### 포함
- "추천받기" 클릭 시 지역·인원수·예산을 바탕으로 웹검색을 돌려 실제 평점·리뷰수를 가진 회식 장소 후보를 조사하고, 상위 5곳을 추천한다
- 생성은 수 분 걸릴 수 있어 백그라운드 작업으로 진행되고, 사용자는 화면을 벗어나거나 새로고침해도 나중에 돌아와 완료된 결과를 확인할 수 있다
- 같은 지역·인원수·예산 조합은 일정 시간(6시간) 동안 캐시된 결과를 재사용해 대기 없이 즉시 보여준다
- 생성 실패 시 실패 안내와 재시도 버튼을 제공한다
- 회식에 어울리는 업종(고깃집·이자카야·호프·횟집·일식 등)만 후보로 삼도록 웹검색에 업종을 명시한다
- 저장(선택 저장·목록 조회·삭제)·카톡 공유·투표 만들기·참석자 투표는 실시간 생성된 장소에 대해서도 기존과 동일하게 동작한다

### 제외
- 지역 자유 텍스트 입력 — 기존처럼 미리 정의된 6개 지역(오산역/오산운암/동탄역/동탄호수/동탄1/강남) 드롭다운을 그대로 쓴다
- 생성 실패 시 시드 데이터로 폴백 — 실측 데이터와 시드 데이터가 섞이면 사용자가 무엇을 보고 있는지 혼란스러워진다. 실패는 실패로 보여주고 재시도를 유도한다
- "추천받기" 버튼에 대한 비밀번호 잠금 — 사용자가 나중에 별도로 결정하기로 미뤘다 (미결정 항목 참고)
- 결과 개수·정렬 기준(예산적합도→평점→리뷰수→조회수) 변경 — 기존 로직 그대로, 데이터 소스만 바뀐다

## 시나리오

### 1. 처음 조회하는 조합으로 추천받기 (캐시 없음)
- **Given** 사용자가 홈 화면에서 지역·인원수·예산을 입력했고, 이 조합은 6시간 내 요청된 적이 없다
- **When** "추천받기" 버튼을 클릭한다
- **Then** 결과 화면으로 이동해 생성이 진행 중이라는 안내가 표시되고, 완료되면 웹검색으로 조사된 평점·리뷰수를 가진 상위 5곳이 카드로 표시된다

성공 기준:
- [ ] 지역="강남", 인원수=8, 예산=30000 입력 → 결과 화면에 "추천 장소를 찾고 있어요" 같은 진행 중 안내가 먼저 보인다
- [ ] 생성 완료 후 카드 5개(장소명, 카테고리, 평점, 리뷰수, 1인 예상 비용)가 표시된다
- [ ] 표시된 평점·리뷰수는 하드코딩된 고정값이 아니라 이번 요청에서 조사된 값이다

### 2. 생성 중 화면을 벗어났다 돌아오기
- **Given** 추천 생성이 진행 중이다
- **When** 사용자가 다른 화면으로 이동하거나 브라우저를 새로고침한 뒤, 다시 같은 결과 화면으로 돌아온다
- **Then** 그 사이 생성이 끝났다면 결과가 바로 보이고, 아직 진행 중이라면 진행 중 안내가 계속 보인다 (처음부터 다시 시작하지 않는다)

성공 기준:
- [ ] 생성 진행 중 새로고침 → 같은 진행 중 안내가 이어서 보이고 생성이 처음부터 재시작되지 않는다
- [ ] 생성이 백그라운드에서 완료된 뒤 결과 화면 재진입 → 대기 없이 바로 완성된 카드 5개가 보인다

### 3. 같은 조합 재요청 시 캐시 재사용
- **Given** 지역="강남", 인원수=8, 예산=30000 조합으로 5분 전에 이미 추천을 받은 적이 있다
- **When** 같은 조합으로 다시 "추천받기"를 클릭한다
- **Then** 새로 검색하지 않고 대기 화면 없이 즉시 이전 결과가 그대로 표시된다

성공 기준:
- [ ] 6시간 이내 동일 조합 재요청 → 진행 중 안내 없이 즉시 카드 5개가 표시된다
- [ ] 6시간이 지난 뒤 동일 조합 재요청 → 다시 웹검색이 진행되고 새 결과가 나올 수 있다

### 4. 생성 실패 시 재시도
- **Given** 웹검색 또는 결과 정리 과정이 실패했다
- **When** 생성이 실패로 끝난다
- **Then** "추천 생성에 실패했어요" 같은 안내와 "다시 시도" 버튼이 표시되고, 버튼을 클릭하면 같은 조건으로 생성을 다시 시도한다

성공 기준:
- [ ] 생성 실패 → 실패 안내 문구와 "다시 시도" 버튼이 보이고, 시드 데이터나 빈 카드로 대체되지 않는다
- [ ] "다시 시도" 클릭 → 같은 지역·인원수·예산으로 새 생성이 시작되고 진행 중 안내로 돌아간다

### 5. 회식 업종 위주로 후보 구성
- **Given** 특정 지역에 카페·편의점 등 회식과 무관한 곳들이 많다
- **When** 추천 결과가 생성된다
- **Then** 표시되는 5곳은 모두 고깃집·이자카야·호프·횟집·일식 등 회식에 어울리는 업종이다

성공 기준:
- [ ] 생성된 카드 5개의 카테고리가 모두 회식용 업종(식사·주류 위주)에 속한다

### 6. 생성된 장소 저장·공유·투표
- **Given** 실시간 생성으로 나온 추천 결과 5곳이 화면에 표시되어 있다
- **When** 카드 2개를 선택해 저장하거나, 카톡으로 공유하거나, 투표를 만든다
- **Then** 시드 데이터 시절과 동일하게 저장 목록에 반영되고, 공유 텍스트에 포함되고, 투표 후보로 등록된다

성공 기준:
- [ ] 생성된 카드 2개 체크 후 저장 → 저장 목록에서 그 2곳이 정상적으로 보인다
- [ ] 생성된 카드 5개로 카톡 공유 → 공유 텍스트에 5곳 이름이 모두 포함된다
- [ ] 생성된 카드 일부를 후보로 투표 만들기 → 투표 화면에서 정상적으로 득표·마감 처리된다

## 불변 규칙

- 캐시 유효 시간(6시간) 동안은 같은 지역·인원수·예산 조합에 대해 새 웹검색을 돌리지 않는다.
- 화면에 표시되는 평점·리뷰수는 항상 해당 결과가 생성된 시점의 웹검색 조사값이며, 고정된 하드코딩 값이 아니다.
- 저장·카톡 공유·투표 기능은 장소 데이터의 출처(시드 vs 실시간 생성)와 무관하게 동일하게 동작한다.
- 생성 실패는 시드 데이터나 빈 결과로 조용히 대체되지 않고, 항상 사용자에게 실패로 보여진다.

## 의존성

- 기존 venue-recommendation 기능(입력 폼, 결과 화면, 저장·투표·카톡 공유)이 이미 구현되어 있어야 한다.
- 웹검색 기반 생성을 수행할 수 있는 인증 경로(구독 인증 또는 API 키)가 준비되어 있어야 한다.

## 미결정 항목

- "추천받기" 버튼에 대한 비밀번호 잠금 범위(추천받기만 vs 쓰기 전체) — 사용자가 나중에 별도로 결정하기로 미뤘다.
